
# RunStop Mobile 통합 / 실기기 테스트 작업 계획 수립

이번 작업에서는 코드를 수정하거나 구현하지 마세요.
먼저 현재 저장소를 충분히 분석한 뒤, 이후 구현을 위한 "실행 계획"만 작성하세요.

목표는 기존 팀원의 Mobile 작업 결과를 최대한 보존하면서,
필요한 경우 personal/hurwan 브랜치에서 부족한 부분만 보완하여
최종적으로 Android APK를 실제 휴대폰에 설치하고,
외부 네트워크(LTE/5G) + GPS 환경에서 RunStop의 핵심 흐름을
End-to-End로 테스트할 수 있는 상태를 만드는 것입니다.

6. Android / Native / APK 준비 점검
==================================================

현재 프로젝트 기준으로 아래를 확인하세요.

- Expo version
- React Native version
- expo-location
- expo-secure-store
- expo-dev-client
- Naver Map Native module
- app.json plugin 설정
- Android package name
- foreground location permission
- INTERNET permission

그리고 실제 야외 사용을 위한 APK 생성 경로를 두 가지로 분리하세요.

A. EAS Build

목표:
Android SDK를 로컬에 완전히 구성하지 않고
Cloud에서 installable APK 생성.

확인할 것:
- EAS CLI 필요 여부
- Expo 로그인
- eas.json 존재 여부
- preview profile 존재 여부
- android.buildType = apk 여부
- EXPO_PUBLIC_API_BASE_URL 주입 방법
- 결과 APK download URL

B. Local Native Build

목표:
JDK + Android SDK가 준비되어 있을 경우
로컬에서 APK 생성.

확인할 것:
- android/ 디렉터리 존재 여부
- expo prebuild 필요 여부
- gradlew.bat 사용 가능 여부
- Debug APK / Release APK 차이
- 출력 파일 경로

두 방식을 비교하고,
현재 프로젝트에서 발표 및 야외 테스트용으로
어느 쪽이 더 안전한지 추천하세요.

→ 러닝 시작
→ GPS 이동
→ Trackpoint 전송
→ 서버 DB 저장
→ Finish
→ distance / pace 확인

↓

↓
노트북

프로젝터
