## 2. 현재 서비스 개요

RunStop은 사용자의 러닝 조건과 공간 데이터를 이용해
**단순 최단 경로가 아니라 실제 러닝 조건에 맞는 코스 후보를 생성하고 추천하는 서비스**이다.

주요 Feature 후보:
- 목표 거리
- 경사도 / 누적 상승고도
- 화장실 / 편의점
- 공원 / 환경
- 가로등 / 보안등 / CCTV
- 보행 가능 경로
- 사용자 추가 조건

현재 서비스 흐름:

```text
회원가입 / 로그인
        ↓
사용자 정보 / 선호 설정
        ↓
러닝 조건 입력
        ↓
자연어 조건 구조화 + 검증
        ↓
경로 후보 생성
        ↓
Route Feature 계산
        ↓
조건 검사 / 점수화 / Ranking
        ↓
추천 코스 최대 3개
        ↓
사용자 선택
        ↓
러닝 시작 / GPS 기록
        ↓
러닝 종료 / 기록 저장
```

## 5. 진행 중 변경된 핵심 결정

### 인증

과거:
```text
Google OAuth 중심
```

현재:
```text
자체 회원가입
→ 자체 로그인
→ bcrypt
→ JWT
```

이유:
- 자체 인증이 어차피 필요
- OAuth Provider 간 계정 병합 비용이 큼
- 현재 프로젝트 범위에서는 자체 인증이 단순

### Node ↔ Python

과거 PoC:
```text
Node child_process
→ Python stdin/stdout
```

현재:
```text
Node Backend
→ Internal HTTP
→ FastAPI Routing Worker
```

이유:
- Node/Python Runtime 분리
- Worker 독립 재시작
- Worker 수평 확장 가능
- Docker 구조 명확
- Raw TCP / RabbitMQ보다 현재 비용이 낮음

과거 child_process 코드는 **역사적 PoC**로 본다.

### 환경변수

기준:
```text
.env.development
.env.test
.env.production
.env.example
```

공식 설정 위치는 프로젝트 Root.

Docker 내부:
```text
WORKER_URL=http://routing-worker:8000
DATABASE_URL=...@database:5432/runstop
```

로컬 직접 실행:
```text
WORKER_URL=http://localhost:8000
DATABASE_URL=...@localhost:5432/runstop
```
