# (임시) RunStop 멘토링 질문

## 현재 고려 중인 구조

학습 단계에서는
1. 알고리즘 결과를 학습하는 경로 생성 AI
2. 생성된 후보 중 적합한 경로를 선택하는 경로 추천 AI

두 모델을 분리하여 학습하고,
서비스에서는 두 과정을 하나의 파이프라인으로 연결할 예정입니다.


## 질문

1. Dijkstra 등의 알고리즘으로 생성한 경로를 학습시켜,
   AI가 더 적은 연산으로 유사한 경로를 생성하도록 하는 방식이 타당할까요?
   알고리즘으로 명확히 해결 가능한 문제를 AI로 근사할 때 특히 고려할 점이 궁금합니다.

2. 경로 생성 AI와 경로 추천 AI를 모두 구현하면 프로젝트 범위가 너무 커질까요?
   하나를 줄인다면 어느 부분을 알고리즘으로 유지하는 것이 적절할까요?

3. 여러 경로 후보를 팀에서 평가하여 추천 모델의 학습 데이터를 만들려고 합니다.
   이때 평가 기준, 라벨 방식, 데이터 수 등에서 주의할 점이 있을까요?

4. 경사도, 가로등, CCTV, 화장실, 편의점, 보행자도로 등의 공간 데이터를
   경로 단위 Feature로 가공해 모델에 사용하는 방식은 적절할까요?

5. 경로 알고리즘, AI 모델, 공간 데이터, TMAP 등의 외부 API를
   하나의 서비스로 연결할 때 예상되는 주요 충돌 지점이나 병목은 무엇일까요?

6. 현재 `프론트엔드`는 피그마와 AI를 활용한 빠른 구현 / `백엔드` / `AI 모델링` / `데이터 파이프라인 구성` 등으로 분업을 고려하고 있습니다.
   프로젝트 규모에서 더 효율적인 분업 방식이 있을까요?

7. 현재 기획에서 구현 비용에 비해 가치가 낮거나,
   프로젝트 완성도를 위해 과감히 제외하는 것이 좋을 부분이 있다면 무엇일까요?

8. 기능 구현을 넘어 실제 서비스처럼 완성도를 높이기 위해
   현업에서 특히 신경 쓰는 부분이나 요령이 있다면 궁금합니다.
