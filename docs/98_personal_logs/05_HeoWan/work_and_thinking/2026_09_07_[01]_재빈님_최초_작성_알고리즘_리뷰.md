현재 재빈님이 작성하신 알고리즘을 그대로 서버에 붙인 뒤 쭉 읽고 이해하였습니다.

현재 기준 커밋 태그 링크는 [여기](https://github.com/hurwan0629/RunStop/commit/2a952ec0ce55ecbfbbf7bda60634a40d0a1c2151)입니다.

전체적인 흐름은

1. 사용자 요청의 MODE[ONE_WAY | LOOP | ROUND_TRIP] 와 추가 변수인 { end, vias }가 있는지에 따라 다음과 같이 나뉘게 됩니다.

- vias가 있는 경우: 모든 반환값이 `mode=via`로 설정되어있습니다.
    - `pipeline._generate_via()` 함수를 호출.(그런데 왜 이게 pipeline 파일에 있는건지는 잘 모르겠음.) 내부적으로 `course.generate_course_via()`, `course._route_chain()`, `route.shortest_path()`를 순서대로 호출하여 경로를 생성합니다.
        - `MODE=ONE_WAY`: end 변수가 반드시 있어야하며 없는 경우에는 에러를 터트립니다.
        - `MODE=LOOP`: end변수가 존재하더라도 start 포인트를 tail로 설정하여 원을 이용한 거리를 계산합니다.
        - `MODE=ROUND_TRIP`: `MODE=LOOP`와 완벽하게 동일한 방식으로 동작합니다.
- vias가 없는 경우: 
    - `candidates.generate_candidates()` 함수를 호출합니다. 내부적으로 `course.generate_course()`, `course._build()`를 이용하여 `._build()`에서 `MODE`를 분기하여 처리해줍니다. 또한 `MODE=ONE_WAY`일 경우 `end`가 없으면 `course.generate_course()`에서 처리해주게 됩니다.
        - `MODE=ONE_WAY`: 타원의 양 초점과 타원위의 점의 거리가 같다는 특성을 이용하여 waypoint를 1개 생성하여 경로를 만들어줍니다. 
        - `MODE=LOOP`: 원 방식을 이용하여 하나의 경로를 생성한 이후에 `penalty_edges` 를 주는 방식의 `route.shortest_path()`를 호출하여 다른 경로를 받아줍니다.
        - `MODE_ROUND_TRIP`: 갔던 거리와 동일한 경로를 뒤집어서 더해줍니다.

대강 매우 큰 흐름은 위와 같으며, 이런저런 부분에서 보안할 부분은 내일 재빈님과 이야기해보기로 하였습니다.
