# G - MultiDiGraph

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `routing-worker/src/algo/utils/graph.py`
> - **역할:** 서울 보행 도로망을 직접 들고 다니며 NetworkX 라우팅과 OSM 속성 분석에 사용한다.
> - **이전 단계:** [[01. Coordinate와 좌표계]]
> - **다음 단계:** [[03. NodeIndex]]
> - **주요 입력:** 서울_보행네트워크.graphml
> - **주요 출력:** networkx.MultiDiGraph G

## 최소 스키마

```text
G: networkx.MultiDiGraph

Node
├─ x : longitude
├─ y : latitude
└─ 기타 OSM node 속성

Edge
├─ length : meter
└─ 기타 OSM edge 속성
```

실제 라우팅/분석에서는 다음 속성도 사용될 수 있다.

| 위치 | 속성 | 현재 사용처 |
|---|---|---|
| edge | `length` | 기본 거리 비용, 실제 거리 |
| edge | `highway` | 계단/보행친화/대로 판단 |
| edge | `grade`, `grade_abs` | 경사 constraint / penalty |
| edge | `surface` | poor surface penalty |
| edge | `lit` | 야간 safety penalty |
| edge | `leisure`, `natural`, `landuse`, `waterway` | nature penalty |
| node | `highway` | `traffic_signals`, `crossing` 판정 |

## 왜 MultiDiGraph인가?

같은 `u → v` 사이에 여러 edge가 존재할 수 있다.

```text
u ── edge key 0 ──→ v
u ── edge key 1 ──→ v
```

Weighted Dijkstra의 callback은 이 평행 edge들을 각각 평가한 뒤 허용된 비용 중 최소값을 반환한다.

> [!warning] 인지된 한계
> 현재 Dijkstra의 비용 선택은 평행 edge별로 하지만, 이후 실제 거리/Surface 분석에서는 `u,v`만 남아 가장 짧은 raw edge를 다시 고른다. 동일한 edge key를 끝까지 보존하지 않으므로 세부 속성이 달라질 여지가 있다. **인지 완료 / 추후 개선 검토 대상**.
