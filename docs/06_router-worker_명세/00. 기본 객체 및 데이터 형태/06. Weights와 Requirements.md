# Weights와 Requirements

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `routing-worker/src/algo/types.py, scoring/normalization.py, scoring/constraints.py`
> - **역할:** 사용자 선호(soft preference)와 반드시 지켜야 하는 조건(hard constraint)을 구분한다.
> - **이전 단계:** [[05. RouteType과 RouteMode]]
> - **다음 단계:** [[07. CandidateRoute와 데이터 생명주기]]
> - **주요 입력:** 사용자 프로필/요청에서 만들어진 dict
> - **주요 출력:** 경로 생성과 최종 점수화에 전달되는 설정

## 타입

```python
Weights: TypeAlias = dict[str, int]
Requirements: TypeAlias = dict[str, bool | int | float]
```

## 역할 차이

```text
Requirements
→ 이 edge/경로가 허용되는가?

Weights
→ 허용되는 선택지 중 무엇을 더 선호하는가?
```

현재 예:

```python
weights = {
    "distance": 5,
    "elevation": 4,
    "toilet": 5,
    "store": 2,
    "park": 3,
    "night": 5,
    "surface": 3,
    "flow": 2,
    "overlap": 5,
}

requirements = {
    "toilet": True,
    "store": False,
    "park": False,
    "no_stairs": True,
    "max_slope_pct": 8,
}
```

## 두 번 사용되는 사용자 선호

Weights는 하나의 단계에서만 쓰이지 않는다.

```text
1) 경로 생성
weights → edge cost → 어떤 경로가 만들어질지 영향

2) 점수화
weights → sub-score 가중평균 → 후보 순위에 영향
```

`toilet`, `store`처럼 Graph edge에 직접 존재하지 않는 정보는 현재 edge cost 생성에는 직접 사용되지 않고 최종 feature/score에서 의미가 커진다.

> [!note] 변경 예정
> population prior / 개인 프로필 / 현재 요청을 조합하여 weights를 구성하는 방식은 논의됐지만 **아직 구현되지 않았다**.
