# CandidateRoute와 데이터 생명주기

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `routing-worker/src/algo/types.py`
> - **역할:** 후보 경로가 생성→특징추출→점수화 단계에서 어떤 필드를 갖게 되는지 정의한다.
> - **이전 단계:** [[06. Weights와 Requirements]]
> - **다음 단계:** [[../01. 후보 경로 생성/INDEX|01. 후보 경로 생성]]
> - **주요 입력:** 각 계층의 계산 결과
> - **주요 출력:** CandidateRoute TypedDict

## 1단계 — 후보 생성 직후

```python
{
    "mode": ...,
    "target_distance_m": ...,
    "actual_distance_m": ...,
    "distance_error_pct": ...,
    "overlap_ratio": ...,
    "scale_m": ...,
    "coords": [...],
    "nodes": [...]
}
```

## 2단계 — Feature 추가 후

```python
{
    # 기존 필드 +
    "slope": {
        "avg_slope_pct": ...,
        "max_slope_pct": ...,
        "slope_std_pct": ...,
        "elevation_gain_m": ...,
        "elevation_loss_m": ...,
        "sample_count": ...,
    },
    "facilities": {...},
    "nature": {...},
    "surface": {...},
}
```

## 3단계 — Scoring 후

```python
{
    # 기존 필드 +
    "sub_scores": {...},
    "condition_score": ...,
    "failed_conditions": [...],
    "exact_match": ...,
    "estimated_minutes": ...,
}
```

`pipeline.recommend()`은 scoring이 끝나면 내부 분석용 `nodes`를 제거한 뒤 응답 후보로 사용한다.

> [!tip]
> 문서를 읽을 때 “cand에 지금 어느 단계의 필드까지 붙어 있는가?”를 확인하면 함수의 역할을 빠르게 파악할 수 있다.
