# 점수화 - 현재 한계점

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `routing-worker/src/algo/scoring/weighting.py`
> - **역할:** 현재 heuristic scoring의 임계값, 사용자 profile, 설명/AI 역할에 대한 개선 대상을 기록한다.
> - **이전 단계:** [[06. condition_score와 결과값]]
> - **다음 단계:** [[../99. 사용 데이터 출처/INDEX|99. 사용 데이터 출처]]
> - **주요 입력:** 현재 scoring 구현
> - **주요 출력:** 수정/검토 체크리스트

| ID | 현재 상태/한계 | 상태 | 예정 방향 |
|---|---|---|---|
| SCORE-01 | 0/100 기준 대부분 수동 heuristic | 인지 완료 | 실제 후보 분포/사용자 선택 데이터로 튜닝 |
| SCORE-02 | 예상 pace가 6 min/km 고정 | 인지 완료 | 사용자 프로필/최근 러닝 pace 활용 검토 |
| SCORE-03 | `_DEFAULT_W`가 수동 fallback | 인지 완료 | population prior/개인 profile 설계 검토 |
| SCORE-04 | edge-level max slope와 최종 failed-condition 정합성 부족 | 인지 완료 | requirement 계층 정리 |
| SCORE-05 | `crossing_per_km`는 측정하지만 현재 flow sub-score에는 직접 미사용 | 인지 완료 | 필요성 검토 |
| SCORE-06 | surface의 의미가 코드명보다 넓음 | 인지 완료 | 코드명 유지 + 명세에서 “도로 환경 프로파일”로 설명 |
| SCORE-07 | AI ranking과 heuristic score의 최종 역할이 아직 미확정 | 예정 | AI 구현 시 결정 |

## 현재 문서화 원칙

현재 점수는 “정답 확률”이 아니다.

> **서비스가 정의한 heuristic 기준으로 raw feature를 0~100 적합도로 변환하고 사용자 중요도를 반영한 점수**

로 설명한다.
