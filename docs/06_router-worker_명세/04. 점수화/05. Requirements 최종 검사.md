# Requirements 최종 검사

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `routing-worker/src/algo/scoring/weighting.py::check_requirements`
> - **역할:** edge-level constraint와 별개로 완성된 후보 경로가 서비스 필수조건을 만족하는지 기록한다.
> - **이전 단계:** [[04. 사용자 Weight 가중평균]]
> - **다음 단계:** [[06. condition_score와 결과값]]
> - **주요 입력:** CandidateRoute, Requirements
> - **주요 출력:** failed_conditions, exact_match

## 현재 검사

경로 자체:

```text
distance_error_pct <= 10%
```

사용자 요구가 True일 때:

```text
toilet → toilet_count >= 1
store  → store_count >= 1
no_stairs → stairs_count == 0
park   → park_ratio >= 0.05
```

반환:

```python
(failed_conditions, len(failed_conditions) == 0)
```

## edge-level constraint와 다르다

```text
constraints.py
→ Dijkstra 전에 edge 통과 자체를 차단
→ no_stairs, max_slope

weighting.check_requirements
→ 완성 경로를 보고 결과를 기록
→ distance, toilet, store, stairs, park
```

후보는 `failed_conditions`가 있어도 현재 scoring 단계에서 즉시 삭제하지 않는다.

> [!warning] 인지된 불일치
> `max_slope`는 edge 탐색 constraint에는 있지만 현재 `check_requirements()`의 최종 경로-level failed condition에는 직접 포함되지 않는다. **인지 완료 / 정합성 검토 대상**.
