# Surface - OSM 도로 환경

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `routing-worker/src/algo/features/surface.py`
> - **역할:** 실제 경로의 OSM edge/node 속성으로 보행친화도로, 대로, 계단, 신호/횡단보도 밀도를 만든다.
> - **이전 단계:** [[04. Nature - 공원과 하천]]
> - **다음 단계:** [[06. Feature Profile 데이터 형태]]
> - **주요 입력:** G, cand.nodes
> - **주요 출력:** SurfaceProfile

## edge 단위 분석

각 `(from_node, to_node)`에 대해 평행 edge 중 raw `length`가 가장 짧은 edge를 선택한다.

그 edge의 `highway`를 이용해:

```text
walkable
→ footway, path, pedestrian, living_street, track,
  steps, corridor, cycleway, residential, unclassified, service

major road
→ primary, secondary, tertiary, trunk, motorway,
  각 link, busway
```

를 분류한다.

## node 단위 분석

경로의 각 node에서:

```text
highway=traffic_signals → signal count
highway=crossing        → crossing count
```

을 센다.

## 현재 출력

```python
{
    "length_m": ...,
    "walkable_ratio": ...,
    "bigroad_ratio": ...,
    "stairs_count": ...,
    "signal_per_km": ...,
    "crossing_per_km": ...,
}
```

`highway` 데이터가 전혀 없는 grid graph 등에서는 ratio/flow 값을 `None`으로 반환한다.

## 이름에 대한 해석

코드명은 `surface`지만 현재 의미는 단순 포장재가 아니다.

> **surface = 노면 + 도로 유형 + 보행친화성 + 일부 이동 흐름을 포함하는 “도로 환경 프로파일”**

현재 코드 이름은 유지하고 문서/명세에서 의미를 명확히 하는 방향이다.
