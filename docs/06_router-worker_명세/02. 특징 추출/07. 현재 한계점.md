# 특징 추출 - 현재 한계점

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `routing-worker/src/algo/features/*`
> - **역할:** Feature 계층의 알려진 중복/결측/휴리스틱 설정과 변경 검토 항목을 정리한다.
> - **이전 단계:** [[06. Feature Profile 데이터 형태]]
> - **다음 단계:** [[../03. AI 후보 랭킹 - 예정/INDEX|03. AI 후보 랭킹 - 예정]]
> - **주요 입력:** 현재 Feature 구현
> - **주요 출력:** 수정/검토 체크리스트

> [!important]
> 아래 항목은 **이미 인지된 현재 상태**다. 아직 구현되지 않은 변경을 현재 기능처럼 적지 않는다.

| ID | 현재 상태/한계 | 상태 | 예정 방향 |
|---|---|---|---|
| FEAT-01 | 시설/Nature 모두 `BUFFER_M=100` 공유 | 인지 완료 | `FACILITY_BUFFER_M`, `NATURE_BUFFER_M` 분리 검토 |
| FEAT-02 | Elevation은 avg/max slope + gain만 보유 | 인지 완료 | slope std, elevation loss/range 추가 검토 |
| FEAT-03 | 시설이 자체 `route_length_km` 재계산 | 인지 완료 | canonical route distance 통일 검토 |
| FEAT-04 | Surface도 자체 `length_m` 재계산 | 인지 완료 | 동일 거리 source 사용 검토 |
| FEAT-05 | 시설의 `count`와 `per_km`는 강한 관련성 존재 | 인지 완료 | count는 UI/requirement, per_km는 ML feature 중심 검토 |
| FEAT-06 | `walklight`는 코드 key는 있으나 현재 CSV에 없다는 주석 | 확인 필요 | 데이터 출처/존재 확인 |
| FEAT-07 | 자연 GeoJSON 파일 없으면 None | 의도된 결측 처리 | AI/scoring에서 결측 정책 명확화 필요 |

## 거리 canonical source 제안 — 아직 미구현

향후:

```text
CandidateRoute.actual_distance_m
= 경로 거리의 단일 진실값

Feature 모듈
= 필요 시 이 값을 전달받아 per-km 계산
```

방향을 검토하고 있다.
