# 시설 통합 CSV

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `서울_시설데이터_통합.csv`
> - **역할:** 서로 다른 공공데이터를 공통 유형/명칭/위도/경도 형태로 통합한 시설 입력의 현재 확인된 출처를 기록한다.
> - **이전 단계:** [[02. DEM 및 등고선]]
> - **다음 단계:** [[04. 공원 및 하천 GeoJSON]]
> - **주요 입력:** 여러 공공데이터/생활안전지도 원본
> - **주요 출력:** 서울_시설데이터_통합.csv

## 알고리즘이 기대하는 현재 유형

```text
화장실
편의점
도시공원
가로등
보안등
보행등
CCTV
```

## 사용자가 현재 확인해 준 원본 링크

- https://www.data.go.kr/data/15075531/fileData.do
- https://www.data.go.kr/data/15028205/standard.do
- https://www.data.go.kr/data/15017320/standard.do
- https://www.safemap.go.kr/opna/data/dataViewRenew.do?objtId=145

> [!note]
> 사용자가 함께 제시한 `https://www.data.go.kr/data/15125058/fileData.do`는 등고선/DEM 쪽 출처로 분류하여 [[02. DEM 및 등고선]]에 기록했다.

## 현재 문서에서 확정하지 않는 것

원본 링크별로 최종 CSV의 어떤 `유형`이 정확히 대응되는지는 **제공된 자료만으로 전체 매핑을 확정하지 않는다.**

특히 현재 추가 확인이 필요한 항목:

```text
CCTV 원본 출처 → 추가 확인 필요
보행등 원본 출처 → 추가 확인 필요
그 외 통합에 사용된 추가 데이터 → 추가 확인 필요
```

## 통합 CSV의 현재 사용 방식

알고리즘은 원본 시설의 세부 속성을 대부분 사용하지 않고:

```text
유형
위도
경도
```

를 중심으로 유형별 좌표 배열을 만들어:

```text
count / per_km / nearest_m
```

feature를 생성한다.

따라서 현재 AI/랭킹 프로젝트 범위에서는 시설별 세부 행정 속성보다 **공간 위치와 유형**이 핵심이다.
