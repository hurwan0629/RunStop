# 거리 Scale 보정

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `routing-worker/src/algo/routing/course.py`
> - **역할:** 원/타원 waypoint의 크기를 반복 조절해 실제 네트워크 경로 길이를 목표거리와 맞춘다.
> - **이전 단계:** [[12. Requirements와 Constraint]]
> - **다음 단계:** [[14. Candidate Pool 필터링]]
> - **주요 입력:** target_distance_m, actual dist, scale
> - **주요 출력:** 가장 오차가 작은 course

## 현재 보정식

\[
scale_{next}
=
scale_{current}
\times
\left(\frac{target}{actual}\right)^{\alpha}
\]

현재 `alpha`는 반복이 진행될수록 작아지고, 최소값은 `0.2`다.

```python
alpha = max(1.0 / (iteration_index + 1), 0.2)
```

예:

```text
목표 4000m
실제 5000m
1회차 → scale × 0.8^1.0

목표 4000m
실제 3200m
2회차 → scale × 1.25^0.5
```

기본 설정:

```text
DIST_FIT_MAX_ITER = 6
DIST_FIT_TOL      = 0.05
```

즉 최대 6회, 오차 `≤5%`면 조기 종료한다.

각 반복에서 가장 낮은 오차를 `best`로 저장하기 때문에 마지막 반복이 나빠져도 그 이전의 더 나은 결과를 반환할 수 있다.

## 왜 수렴이 보장되지 않는가?

Graph 라우팅은 매끄러운 함수가 아니다.

```text
scale 조금 변경
→ 동일 node로 snap
→ 거리 변화 없음

scale 조금 더 변경
→ 다른 node / 다른 shortest path
→ 거리 갑자기 크게 변경
```

따라서 `scale ↑ → actual distance ↑`가 항상 연속적/단조적이라는 보장은 없다.

> [!warning] 인지된 한계
> damping을 적용해도 Graph 라우팅 특성상 수렴이 보장되는 것은 아니다. 현재 구현은 반복 중 가장 오차가 낮았던 경로를 반환하는 방식으로 보완한다.
