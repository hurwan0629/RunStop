# Shortest Path

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `routing-worker/src/algo/routing/shortest_path.py`
> - **역할:** 두 graph node 사이를 사용자 맞춤 edge cost로 NetworkX shortest_path 탐색하고 실제 물리 거리도 계산한다.
> - **이전 단계:** [[09. Waypoint - 타원]]
> - **다음 단계:** [[11. Edge Cost와 사용자 Weight]]
> - **주요 입력:** G, src, dst, penalty_edges, factor, weights, requirements
> - **주요 출력:** NodePath, 실제 거리 m

## 핵심 코드

```python
edge_cost = create_edge_cost_function(
    G,
    weights=weights,
    requirements=requirements,
    used_edges=penalty_edges,
    reuse_factor=factor,
)

nodes = nx.shortest_path(
    G,
    src,
    dst,
    weight=edge_cost,
)
```

즉 Dijkstra가 최소화하는 값은 단순 `length`가 아니라 **callback이 계산하는 personalized cost**다.

## cost와 physical distance는 다르다

```text
Dijkstra cost
= 경로 선택을 위한 가상 비용

actual length
= 실제 도로 길이의 합
```

경로를 찾은 뒤:

```python
length = sum(_edge_len(G.get_edge_data(a, b)) ...)
```

으로 실제 길이를 다시 계산한다.

> [!warning] MultiDiGraph
> callback은 평행 edge 각각의 personalized cost를 비교하지만, `_edge_len()`은 이후 평행 edge 중 raw `length` 최소값을 사용한다. edge key를 경로 결과에 유지하지 않는 현재 구조의 한계다.
