# Waypoint - 타원

> [!info] 빠른 위치 파악
> - **상태:** 현재 구현
> - **소스 위치:** `routing-worker/src/algo/routing/waypoints.py, routing-worker/src/algo/routing/course.py`
> - **역할:** ONE_WAY 또는 Via 거리 부족 시 두 지점을 초점으로 하는 타원 위 우회점을 만든다.
> - **이전 단계:** [[08. Waypoint - 원]]
> - **다음 단계:** [[10. Shortest Path]]
> - **주요 입력:** start/end 또는 last-via/tail, target_sum_m
> - **주요 출력:** 타원 위 Coordinate n개

## 타원의 정의

두 초점 `F1`, `F2`와 타원 위 점 `P`에 대해:

\[
|PF_1| + |PF_2| = 2a
\]

현재:

```python
c = distance(F1, F2) / 2
a = target_sum_m / 2
b = sqrt(a² - c²)
```

`a <= c`이면 목표거리 합이 초점 간 직선거리보다 짧거나 같으므로 타원을 만들 수 없어 `ValueError`다.

## 좌표 생성

축 정렬 타원:

```python
ex = a * cos(t)
ey = b * sin(t)
```

을 start→end 축 각도 `theta`만큼 회전하고 중심으로 이동한다.

현재 `n=8`이므로 parameter angle 기준 8점을 만든다.

## course의 선택 방식

```python
w = ws[int(round(bearing / 45.0)) % 8]
```

> [!warning] 인지된 한계 / 추후 검토
> 외부 `bearing`은 실제 방위각 개념이고, 여기의 `t`는 타원 parameter angle이다. 현재 둘을 index로 직접 대응시키며, 장축 끝점 쪽을 선택하면 목적지를 지나쳤다가 되돌아오는 형태가 생길 가능성도 있다. 또한 기본 12개 bearing을 8개 타원점에 매핑하므로 같은 점이 중복 선택될 수 있다.
>
> 이 문제는 **이미 인지했으며**, 당장은 현재 구현을 문서화하고 이후 타원 waypoint 선택 원리를 재검토하기로 한다.
