# AI 테스트 프로젝트 빠른 실행 가이드

## 목표

처음 저장소를 받은 사람이 **설정 확인 → 테스트 → 데이터 생성 점검 → 실험 실행 → 비교** 흐름을 바로 따라갈 수 있게 한다.

아래 명령은 모두 **RunStop 저장소 루트** 기준이다.

---

# 1. Python 환경

Windows에서는 CPython 3.12 이상을 기준으로 한다.

```powershell
py -3.12 -m venv ai/.venv-win
./ai/.venv-win/Scripts/python.exe -m pip install -r ai/requirements.txt
```

모델 라이브러리를 선택적으로 설치할 수 있다.

```powershell
./ai/.venv-win/Scripts/python.exe -m pip install lightgbm
```

전체 후보 모델을 사용할 경우:

```powershell
./ai/.venv-win/Scripts/python.exe -m pip install -r ai/requirements-models.txt
```

테스트까지 수행할 경우:

```powershell
./ai/.venv-win/Scripts/python.exe -m pip install -r ai/requirements-dev.txt
```

> macOS/Linux에서는 가상환경 Python 경로를 `ai/.venv/bin/python` 등 환경에 맞게 바꾼다.

---

# 2. 가장 먼저 할 검증

```powershell
./ai/.venv-win/Scripts/python.exe -m pytest ai/tests -q
```

이 테스트는 작은 가상 데이터와 임시 Parquet을 사용한다.

실제 서울 전체 공간 데이터를 이용한 추천 품질/처리량 테스트와는 다르다.

UI까지 확인하려면:

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/check_ui.py
```

Windows에 설치된 Edge를 Headless로 사용한다.

---

# 3. 설정 UI 열기

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/config_ui.py
```

브라우저:

```text
http://127.0.0.1:8765
```

UI의 역할:

- 모델 선택
- 모델 파라미터 설정
- Feature 선택
- Split 설정
- 평가 설정
- Generation 설정
- Utility 설정
- YAML 검증 / 저장 / 다운로드 / 가져오기

UI가 하지 않는 것:

- Dataset 실제 생성 실행
- Model 실제 학습 실행
- 운영 Worker 수정
- 운영 모델 자동 배포

즉 **설정 편집기**라고 보는 것이 정확하다.

---

# 4. YAML 템플릿 만들기

Experiment 설정:

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/create_config.py `
  --model xgboost_ranker `
  --output ai/configs/experiments/xgboost_v001.yaml
```

Generation 설정:

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/create_config.py `
  --kind generation `
  --output ai/configs/generation/custom_v001.yaml
```

현재 설정 규격:

```yaml
schema_version: 1
kind: experiment  # 또는 generation
```

모든 상대 데이터/출력 경로는 **`ai/` 기준**으로 해석한다.

---

# 5. Dataset 생성 전 점검

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/generate_dataset.py `
  --config ai/configs/generation/synthetic_v001.yaml `
  --check
```

`--check`는 다음을 확인하는 용도다.

- 설정 유효성
- 입력 JSON
- 필요한 파일 존재 여부
- 경로 설정

실제 공간 데이터 생성은 수행하지 않는다.

실제 Candidate를 만들려면 Routing 관련 의존성이 추가로 필요하다.

```powershell
./ai/.venv-win/Scripts/python.exe -m pip install -r ai/requirements-routing.txt
```

실제 생성:

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/generate_dataset.py `
  --config ai/configs/generation/synthetic_v001.yaml
```

> 실제 그래프 / DEM / 시설 / 공원·하천 데이터가 없으면 중단한다. 테스트용 Grid Graph로 조용히 대체하지 않는다.

---

# 6. Experiment 설정만 검증

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/run_experiment.py `
  --config ai/configs/experiments/lightgbm_compare.yaml `
  --validate-only
```

이 단계에서 설정을 먼저 검증하고 실제 학습은 하지 않는다.

---

# 7. 실제 학습 / 평가

Dataset이 준비된 뒤:

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/run_experiment.py `
  --config ai/configs/experiments/lightgbm_compare.yaml
```

결과는 `ai/artifacts/` 아래 새 Run 디렉터리에 저장된다.

Artifact 내용은 [[06_Artifact와_모델_내보내기]] 참고.

---

# 8. 모델끼리 비교

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/compare_models.py `
  ai/artifacts/RUN_A `
  ai/artifacts/RUN_B
```

비교 시 다음 조건이 다르면 비교를 거부할 수 있다.

- Dataset / Metadata Hash
- 실제 Split
- 평가 설정

이 제한은 숫자만 보고 잘못된 모델 비교를 하지 않기 위한 장치다.

---

# 9. 모델 Export

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/export_model.py `
  --artifact ai/artifacts/RUN_A `
  --output ai/artifacts/export_v001
```

Export 폴더의 독립 추론:

```powershell
python predict.py --input features.parquet --output scores.parquet
```

---

# 실행 흐름 요약

```text
pytest
  ↓
config_ui / create_config
  ↓
generate_dataset --check
  ↓
generate_dataset
  ↓
run_experiment --validate-only
  ↓
run_experiment
  ↓
compare_models
  ↓
export_model
```
