# RunStop AI 테스트 프로젝트 개요

## 0. 목표

RunStop의 기존 경로 생성 알고리즘은 먼저 여러 Candidate Route를 만든다.

AI의 역할은 새로운 길을 직접 만드는 것이 아니라, 만들어진 후보를 사용자에게 더 적합한 순서로 **재정렬(Ranking)** 하는 것이다.

```text
User / Request
      ↓
Routing Worker
      ↓
Candidate Routes 6~10개
      ↓
Feature 정리
      ↓
Ranking Model
      ↓
Top-K
```

현재 `ai/` 폴더는 이 Ranking 모델을 운영에 붙이기 전에 **오프라인에서 검증하기 위한 독립 실험 환경**이다.

---

# 1. 왜 별도의 AI 실험 환경으로 분리했는가

운영 코드에서 바로 모델을 바꾸면 다음 문제가 생긴다.

- 모델마다 데이터 전처리가 달라질 수 있음
- Split이 달라지면 지표를 직접 비교하기 어려움
- 실험할 때마다 결과 파일 형식이 달라질 수 있음
- 합성 Ground Truth와 운영 점수가 섞이면 모델이 기존 휴리스틱을 복제할 수 있음
- 실패한 실험의 설정과 환경을 다시 재현하기 어려움

그래서 현재 구조는 다음을 고정한다.

```text
Dataset Contract
      +
Split Contract
      +
Model Score Contract
      +
Evaluation Contract
      +
Artifact Contract
```

모델은 이 계약 안에서만 교체한다.

---

# 2. 현재 문제 정의

## 입력

한 요청에 대해 여러 후보 경로가 존재한다.

각 후보에는 예를 들어 다음 Feature가 있다.

- 실제 거리 / 목표 거리 오차
- 평균·최대 경사
- 화장실·편의점 등 시설 밀도
- 야간 관련 시설 밀도
- 공원·하천 인접률
- 신호등·횡단보도 밀도
- 보행 가능 Surface 비율
- 경로 중복 비율
- 사용자 Profile Weight
- 현재 Request Weight / Requirement

## 출력

모델은 후보마다 **점수 하나**를 반환한다.

```text
candidate_A → 1.28
candidate_B → 0.71
candidate_C → -0.05
```

높은 점수부터 정렬한다.

> 모델 점수는 공통적으로 "확률"을 의미하지 않는다. 모델 간 절대 점수 크기를 비교하지 않고 같은 요청 안의 순서에 사용한다.

# 3. Ground Truth의 현재 의미

실제 사용자 선택 로그가 충분하지 않기 때문에 지금은 `preference_v1`이라는 **합성 Utility 함수**로 정답을 만든다.

```text
Raw Candidate Features
        +
Synthetic User Preference
        +
Request Preference / Requirement
        ↓
Utility [0, 1]
        ↓
Ground Truth Rank
        +
Relevance Grade
```

중요한 점은 다음과 같다.

> 현재 실험은 "실제 사용자가 좋아하는 경로를 맞추는가"를 직접 증명하는 실험이 아니라, **정의한 합성 선호 규칙을 모델이 얼마나 잘 학습하는가**를 검증하는 단계다.

Utility 상세는 [[02_데이터_생성과_Utility]] 참고.

---

# 4. 현재 지원 모델

| 모델 | 학습 방식 |
|---|---|
| `condition_score_baseline` | 기존 휴리스틱 점수를 그대로 정렬 |
| `logistic_regression` | 같은 요청 안의 후보 Pair 선호를 학습 |
| `random_forest` | Utility 값을 Pointwise 회귀 |
| `lightgbm_ranker` | relevance + request group, LambdaRank |
| `xgboost_ranker` | relevance + request group, `rank:ndcg` |
| `catboost_ranker` | relevance + request group, YetiRank |
| `ranknet` | 후보 Pair의 상대 선호를 Neural Network로 학습 |

모델별 목적함수는 달라도 최종 공통 인터페이스는 같다.

```python
model.fit(train_df, validation_df)
scores = model.predict_scores(candidate_df)
```

# 5. 현재 평가 구조

현재 실제 `selected` 로그를 가정해서 만들지 않는다.

따라서 평가 중심은 다음이다.

- **NDCG@K**: 상위 K개의 relevance 순서 품질
- **Top1 Best Utility**: 예측 1위가 실제 최대 Utility 후보인가
- **Utility Regret**: 최적 Utility와 예측 1위 Utility의 차이
- **Pairwise Accuracy**: Utility가 다른 후보 쌍의 순서를 얼마나 맞추는가

평가는 Overall / Warm / Cold로 나누어 본다.

자세한 내용은 [[03_모델_학습과_평가]] 참고.

# 6. 운영 시스템과의 경계

현재 구조는 다음 경계를 지킨다.

```text
[운영]
routing-worker
  └─ Candidate 생성

[오프라인 AI]
ai/
  ├─ Dataset 생성
  ├─ Utility 정답 생성
  ├─ Model 학습
  ├─ Evaluation
  └─ Export
```

`ai/`에서 학습했다고 자동으로 `routing-worker`에 배포하지 않는다.

운영 연결은 **검증된 모델 Export → 별도 Inference Integration** 단계에서 진행한다.

# 7. 이 프로젝트의 완료 기준

현재 단계의 완료는 단순히 모델 하나의 NDCG가 높은 상태가 아니다.

```text
동일 데이터
+ 동일 Split
+ 동일 Metric
+ Baseline 비교
+ 재현 가능한 Artifact
+ 독립 추론 Export
```

이 조건을 만족해야 모델 선택을 논의할 수 있다.
