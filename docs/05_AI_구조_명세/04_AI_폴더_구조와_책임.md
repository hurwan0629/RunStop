# AI 폴더 구조와 책임

## 목표

`ai/`에서 어떤 파일을 수정해야 하는지 빠르게 찾기 위한 구조 문서다.

---

# 1. 큰 구조

```text
ai/
├─ configs/
├─ datasets/
├─ docs/
├─ scripts/
├─ src/
├─ tests/
├─ requirements*.txt
├─ pytest.ini
├─ NOTES_먼저_결정할_것.md
└─ README.md
```

핵심 흐름은 다음과 같다.

```text
configs
  ↓
scripts
  ↓
src
  ↓
dataset / model / evaluation
  ↓
artifacts
```

---

# 2. configs/

YAML 기반 실행 설정을 둔다.

```text
configs/
├─ README.md
├─ experiments/
│  ├─ lightgbm_compare.yaml
│  └─ model_candidates.example.yaml
└─ generation/
   └─ synthetic_v001.yaml
```

역할:

- Experiment 설정
- Generation 설정
- Model Parameter
- Feature 선택
- Split / Metric / Utility 설정

파라미터의 실제 허용 범위는 `src/config/schema.py`가 Single Source of Truth 역할을 한다.

---

# 3. datasets/

현재 합성 사용자 입력과 생성 스크립트가 있다.

대표 파일:

```text
datasets/
├─ generate_runstop_synthetic_users.py
├─ runstop_users_1000_5000_requests.json
└─ previous_version/
```

주의:

> 원본 Synthetic User 생성기와 JSON은 AI Experiment Pipeline과 구분해서 다룬다.

`generate_dataset.py` 실행이 이 원본 파일 자체를 덮어쓰는 구조로 사용되어서는 안 된다.

---

# 4. scripts/

사용자가 직접 실행하는 CLI 진입점이다.

```text
scripts/
├─ config_ui.py
├─ check_ui.py
├─ create_config.py
├─ generate_dataset.py
├─ run_experiment.py
├─ compare_models.py
├─ export_model.py
├─ predict.py
└─ _bootstrap.py
```

| Script | 역할 |
|---|---|
| `config_ui.py` | 로컬 설정 UI 실행 |
| `check_ui.py` | Headless UI 검증 |
| `create_config.py` | 기본값이 채워진 YAML 생성 |
| `generate_dataset.py` | Candidate Dataset 생성 / 사전 점검 |
| `run_experiment.py` | 모델 학습·평가 실행 |
| `compare_models.py` | 호환되는 Artifact끼리 비교 |
| `export_model.py` | 독립 추론 번들 생성 |
| `predict.py` | 점수 예측 진입점 |

---

# 5. src/config/

```text
src/config/
├─ loader.py
└─ schema.py
```

역할:

- YAML Parsing
- Strict Validation
- Model별 Parameter Schema
- Generation / Experiment Config 규격

새 Model Parameter를 UI에 추가하고 싶다면 HTML부터 수정하는 것이 아니라 **Schema를 먼저 수정**하는 구조다.

---

# 6. src/dataset/

```text
src/dataset/
├─ features.py
├─ loader.py
├─ schema.py
└─ splits.py
```

역할:

- Dataset Schema 검사
- Feature Column 구성
- Parquet Load
- Train / Validation / Warm / Cold Split
- Leakage 방지

Dataset Contract를 수정할 때 가장 먼저 확인하는 영역이다.

---

# 7. src/generation/

```text
src/generation/
├─ candidate_worker.py
├─ pipeline.py
├─ request_sampler.py
├─ user_sampler.py
└─ utility.py
```

역할:

```text
User Sampling
→ Request Sampling
→ Worker Candidate Generation
→ Feature 조립
→ Utility / Rank / Relevance
→ Dataset Output
```

특히:

- `candidate_worker.py`: 기존 Routing Worker와의 격리된 연결
- `pipeline.py`: 전체 데이터 생성 흐름
- `utility.py`: 합성 정답 규칙

Utility를 수정하면 기존 Dataset을 그대로 재사용해서는 안 된다.

---

# 8. src/models/

대표 구조:

```text
src/models/
├─ base.py
├─ pairs.py
├─ registry.py
└─ implementations/
   ├─ condition_score_baseline.py
   ├─ logistic_regression.py
   ├─ random_forest.py
   ├─ lightgbm_ranker.py
   ├─ xgboost_ranker.py
   ├─ catboost_ranker.py
   └─ ranknet.py
```

역할:

- 공통 Ranking Model Interface
- Pairwise Sample 구성
- Model Registry
- 실제 구현

새 모델 추가 시 일반 순서:

```text
Config Schema
→ ModelConfig name
→ Registry
→ BaseRankingModel 구현
→ Test
→ Export dependency 등록
```

---

# 9. src/metrics/ · src/evaluation/

대표 파일:

```text
src/metrics/ranking.py
src/evaluation/cohorts.py
src/evaluation/evaluator.py
```

역할:

- NDCG
- Top1 Best Utility
- Utility Regret
- Pairwise Accuracy
- Overall / Warm / Cold 집계
- Confidence Interval 계산

모델 코드 안에서 각자 Metric을 계산하지 않고 평가 계층을 공유한다.

---

# 10. src/experiment/

```text
src/experiment/
├─ runner.py
└─ artifacts.py
```

역할:

```text
Config Load
→ Dataset Load
→ Split
→ Model Create
→ Fit
→ Predict
→ Evaluate
→ Artifact 저장
```

실험 전체 Orchestration 계층이다.

---

# 11. src/monitoring/

```text
src/monitoring/resources.py
```

역할:

- Wall Time
- CPU Time
- RSS Sampling
- Model Bundle Size 등

모델 정확도뿐 아니라 운영 비용까지 비교할 수 있도록 별도로 측정한다.

---

# 12. src/web/ · src/visualization/

이 영역은 로컬 설정 UI와 실험 결과 표현을 담당하는 계층이다.

핵심 원칙은 다음과 같다.

> Web UI는 실험 설정을 편집하는 도구이지, 임의 서버 실행 API를 제공하는 운영 제어판이 아니다.

---

# 수정 위치 빠른 찾기

| 하고 싶은 작업 | 우선 확인 |
|---|---|
| Utility 공식 변경 | `src/generation/utility.py` |
| Dataset 컬럼 변경 | `src/dataset/schema.py`, `features.py` |
| Split 변경 | `src/dataset/splits.py` |
| 새 모델 추가 | `src/config/schema.py`, `src/models/registry.py`, 구현 파일 |
| Metric 추가 | `src/metrics/`, `src/evaluation/` |
| 실험 저장 결과 변경 | `src/experiment/artifacts.py` |
| 실행 순서 변경 | `src/experiment/runner.py` |
| UI 설정 필드 변경 | 먼저 Config Schema 확인 |
| Resource 측정 변경 | `src/monitoring/resources.py` |
