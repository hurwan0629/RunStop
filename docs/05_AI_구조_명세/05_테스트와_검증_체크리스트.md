# 테스트와 검증 체크리스트

## 목표

"테스트가 통과했다"가 무엇을 의미하고, 무엇까지는 아직 검증되지 않았는지 구분한다.

---

# 1. 기본 자동 테스트

```powershell
./ai/.venv-win/Scripts/python.exe -m pytest ai/tests -q
```

현재 테스트가 확인하는 대표 범위:

- 모델별 설정 검증
- YAML 저장 / 복원
- JSON 입력 규격 정규화
- Utility와 기존 `condition_score`의 독립성
- Utility 동점 Rank 처리
- Dataset 정답 규격
- User / Request Split 누출 방지
- Split 재현성
- Ranking Metric의 Known Answer
- 가변 Candidate 수
- 7종 Model의 작은 Fit / Predict
- 입력 행 순서 보존
- Model Save / Load
- Artifact 성공 / 실패 기록
- 독립 Export 추론
- 가짜 Worker 응답을 사용한 Parquet 조립
- 기존 출력 경로 덮어쓰기 거부
- Local API의 Config 검증 / 저장 / Load / 경로 제한
- 실행 API 부재 확인

선택 Model Library가 설치되어 있지 않으면 해당 Model Test는 Skip될 수 있다.

---

# 2. UI 테스트

```powershell
./ai/.venv-win/Scripts/python.exe ai/scripts/check_ui.py
```

대표 확인 항목:

- 모델별 설정 폼
- YAML 저장 / 복원
- 잘못된 입력 처리
- Utility 수정
- 모바일 Overflow

UI 테스트는 Headless Edge 기반이다.

---

# 3. 자동 테스트가 증명하지 않는 것

다음은 Unit / Small Integration Test 통과만으로 보장되지 않는다.

- [ ] 실제 서울 Graph 전체에서 Candidate 생성 속도
- [ ] 실제 DEM / 시설 / 공원 / 하천 데이터 로딩 안정성
- [ ] 요청 5,000건 전체 Generation 완료 시간
- [ ] Candidate 확보율
- [ ] 메모리 Peak
- [ ] 실제 대용량 Model 학습 시간
- [ ] 실제 운영 Latency
- [ ] 실제 사용자 만족도
- [ ] Synthetic Utility가 현실 선호를 잘 반영하는지

이 부분은 별도 실험으로 확인해야 한다.

---

# 4. Dataset 검증 체크리스트

- [ ] 동일 Request에 후보가 2개 이상인가
- [ ] 목표 정책상 6~10개 Candidate가 충분히 확보되는가
- [ ] `request_id`가 전체 Dataset에서 유일한가
- [ ] `candidate_id`가 Request 안에서 유일한가
- [ ] `request_sequence`가 사용자 안에서 중복되지 않는가
- [ ] Utility가 `[0,1]`인가
- [ ] Ground Truth Rank가 Utility와 일치하는가
- [ ] Relevance가 Utility 규칙과 일치하는가
- [ ] Infinite Numeric이 없는가
- [ ] Candidate Feature가 모델 입력에 들어가고 Target Column은 제외되는가
- [ ] Metadata Hash 검증이 통과하는가

---

# 5. Split 검증 체크리스트

- [ ] Cold User가 Train에 등장하지 않는가
- [ ] Warm Test가 Known User의 마지막 Request인가
- [ ] Validation이 Warm Test보다 이전 Request인가
- [ ] Request 단위 Candidate가 서로 다른 Split으로 갈라지지 않는가
- [ ] 동일 Seed에서 Split이 재현되는가
- [ ] 최소 요청 수 미달 사용자가 정책대로 제외되는가

---

# 6. Model 검증 체크리스트

- [ ] Predict Score 행 수가 입력 Candidate 수와 같은가
- [ ] Score가 전부 finite인가
- [ ] 높은 Score가 더 높은 Ranking으로 해석되는가
- [ ] 저장 후 Load한 Model이 동일 입력에서 일관된 결과를 내는가
- [ ] Feature Column 순서가 저장된 Schema와 일치하는가
- [ ] Validation / Test로 Preprocessor를 Fit하지 않는가
- [ ] Ranking Model의 Request Group이 올바른가

---

# 7. Evaluation 검증 체크리스트

- [ ] NDCG@K가 Known Example에서 기대값과 일치하는가
- [ ] Utility 동점 Top1이 공동 정답 처리되는가
- [ ] Regret가 낮을수록 좋게 정의되어 있는가
- [ ] Pairwise Accuracy에서 Utility 동점 Pair가 제외되는가
- [ ] Warm / Cold / Overall이 따로 계산되는가
- [ ] CI가 사용자 Cluster 단위로 계산되는가

---

# 8. 실제 대규모 검증 권장 순서

```text
[1] 10~30 Requests Smoke Test
        ↓
[2] 100 Requests Candidate 확보율 / Runtime
        ↓
[3] 1,000 Requests Resource 측정
        ↓
[4] 전체 Generation
        ↓
[5] Baseline Experiment
        ↓
[6] LightGBM 등 1차 Model
        ↓
[7] Multiple Model Compare
        ↓
[8] Human Evaluation Sample
```

처음부터 5,000건 전체를 돌리기보다 작은 단위로 실패 지점을 확인하는 편이 안전하다.

---

# 9. 완료 기준

자동 테스트 완료 기준:

```text
pytest PASS
+ UI CHECK PASS
```

실험 환경 검증 완료 기준:

```text
실제 Candidate Generation 성공
+ Dataset Contract PASS
+ Baseline Experiment 성공
+ Model Experiment 성공
+ Artifact 비교 가능
+ Export 독립 추론 성공
```
