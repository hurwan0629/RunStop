# RunStop AI Artifact 병합 요약

## 목적

`ai/artifacts`에서 학습된 ranking artifact를 routing-worker 후보 선택 단계에 고정 내장한다.

외부 GPT API나 환경변수 기반 모델 선택이 아니라, 검증한 artifact 파일을 `routing-worker/src/algo/ai/artifact/`에 포함해 worker 코드와 함께 배포하는 방식이다.

## 적용 범위

코드 변경은 `routing-worker/src/algo/ai/` 내부로 제한했다.

- `candidate_selector.py`
  - 기존 `condition_score` 정렬 fallback 유지
  - artifact ranking 성공 시 AI score 기준 정렬
- `artifact_ranker.py`
  - 내장 artifact 로드
  - `model.pkl` 예측 호출
  - pickle의 기존 `ai.src...` 클래스 경로를 worker 내부 최소 클래스로 매핑
- `feature_adapter.py`
  - worker candidate dict를 artifact `input_schema.json` 컬럼 형태로 변환
- `artifact/`
  - 선택 artifact의 실행 파일과 참고 메타데이터 복사

## 선택 Artifact

사용 artifact:

```text
ai/artifacts/20260914_045008_lightgbm_ranker_977ee247/model
```

복사 위치:

```text
routing-worker/src/algo/ai/artifact/
```

포함 파일:

- `model.pkl`
- `input_schema.json`
- `metrics.json`
- `manifest.json`

`metrics.json`, `manifest.json`은 런타임 필수는 아니지만 어떤 학습 산출물을 포함했는지 추적하기 위해 함께 둔다.

## 동작 원칙

1. 후보 생성, 경사/시설/자연/도로 feature 계산, 기존 scoring은 그대로 둔다.
2. `select_candidates_with_ai()` 안에서만 artifact model을 호출한다.
3. artifact 로드, feature 변환, 예측 중 하나라도 실패하면 기존 `condition_score` 정렬로 fallback한다.
4. `facilityPreferences=PREFER`는 AI 입력 컬럼의 `requirements_toilet/store=1`로만 반영한다.

## 현재 주의사항

현재 실행 중인 Docker 컨테이너는 소스 볼륨 마운트가 아니라 이미지 빌드 방식이므로, 변경사항은 routing-worker 이미지 재빌드 후 반영된다.

또한 선택한 LightGBM artifact는 런타임에 `scikit-learn`, `lightgbm` 계열 의존성이 필요하다. 현재 실행 중인 routing-worker 컨테이너에서는 해당 패키지가 확인되지 않았으므로, 재빌드 시 requirements 반영 여부를 별도로 결정해야 한다.
