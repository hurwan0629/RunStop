# 코드 변경 기록

## routing-worker/src/algo/ai/candidate_selector.py

후보 선택 단계에서 artifact ranking을 호출하도록 변경했다.

처리 순서:

1. `score_candidates_with_artifact(...)` 호출
2. 반환된 AI score를 기준으로 후보 정렬
3. 상위 `top_k` 반환
4. 실패 시 기존 `condition_score` 내림차순 fallback

fallback 정렬은 다음 기준을 유지한다.

```python
key=lambda candidate: candidate["condition_score"]
```

이 파일은 여전히 후보 생성이나 feature 계산을 수행하지 않는다. 역할은 최종 후보 선택이다.

## routing-worker/src/algo/ai/artifact_ranker.py

내장된 artifact를 로드하고 score를 계산하는 모듈을 추가했다.

주요 책임:

- `artifact/model.pkl` 로드
- `artifact/input_schema.json` 컬럼 검증
- worker 후보를 pandas DataFrame으로 변환
- `model.predict_scores(...)` 호출

pickle은 학습 당시 `ai.src.models...` 경로의 클래스를 참조한다. routing-worker 런타임에는 해당 패키지를 그대로 포함하지 않으므로, 최소 클래스 매핑을 `ArtifactUnpickler`에 두었다.

외부 의존성 또는 pickle 로드 실패는 상위 `candidate_selector.py`에서 잡아 fallback한다.

## routing-worker/src/algo/ai/feature_adapter.py

worker candidate dict를 artifact 입력 schema에 맞는 row로 변환하는 모듈을 추가했다.

매핑 대상:

- candidate 기본 정보
  - 거리
  - 거리 오차
  - 예상 시간
  - 중복 비율
  - exact match
- slope feature
- facilities feature
- nature feature
- surface feature
- request weights
- user weights
- requirements
- route type one-hot

현재 실사용 요청에는 별도 user profile이 없으므로 `user_weight_*`는 `request_weight_*`와 동일하게 채운다.

`facilityPreferences.toilet/store=PREFER`는 AI 입력 경계에서만 `requirements_toilet/store=1`로 변환한다.

## routing-worker/src/algo/ai/artifact/

선택한 LightGBM ranking artifact를 복사했다.

```text
model.pkl
input_schema.json
metrics.json
manifest.json
```

학습 dataset, predictions, plots, runtime source 전체는 포함하지 않았다.
