# RunStop 경로 추천 알고리즘 초안

## 1. 기본 개념

RunStop의 경로 추천은 사용자의 출발지에서 목표 거리와 조건을 만족하는 순환형 러닝 경로를 생성하는 것을 목표로 한다.

기본적인 경로 형태는 다음과 같이 정의한다.

Start -> W1 -> W2 -> ... -> Wn -> Start

- Start: 사용자가 지정한 출발지
- W1 ~ Wn: 경로 생성을 위해 선택된 핵심 경유지(Waypoint)
- Start-W1, W1-W2 등의 각 구간은 실제 보행 가능한 도로를 따라 연결한다.
- 각 핵심 지점 사이에는 하나의 경로만 존재하는 것이 아니라 여러 개의 경로 후보가 존재할 수 있다.
- 각 구간의 후보를 조합하여 여러 개의 전체 순환 경로 후보를 생성한다.
- 최종적으로 전체 경로를 다시 평가하여 상위 3개의 경로를 사용자에게 추천한다.


## 2. 사용자 요구사항 분석

사용자의 요구사항을 크게 세 종류로 분리한다.

### 2.1 필수 조건(Hard Constraint)

반드시 만족해야 하는 조건이다.

예시:
- 출발지
- 목표 거리 5km ± 허용 오차
- 보행 가능한 도로
- 반드시 지나가야 하는 장소
- 특정 지역 제외
- 최대 허용 경사 등

필수 조건을 만족하지 못한 경로는 최종 후보에서 제거한다.


### 2.2 선호 조건(Soft Preference)

만족할수록 경로의 점수를 높이는 조건이다.

예시:
- 경사가 낮은 길 선호
- 가로등이 많은 길 선호
- 보행자전용도로 선호
- 하천 주변 선호
- 녹지가 많은 길 선호
- 편의점이 있는 길 선호


### 2.3 근접 조건(Near Constraint)

특정 위치를 반드시 통과할 필요는 없지만 경로 일정 범위 안에 존재하기를 원하는 조건이다.

예시:
- 2.5km 부근에 화장실이 있었으면 좋음
- 경로에서 편의점까지 100m 이내였으면 좋음
- 한강에서 200m 이내의 길을 지나갔으면 좋음

이러한 조건은 특정 Node를 반드시 통과하도록 만들기보다는 최종 경로 생성 후 접근 거리를 계산하여 평가한다.


## 3. 검색 영역 제한

서울 전체 도로망을 대상으로 탐색하면 연산량이 지나치게 커질 수 있으므로 사용자의 목표 거리에 따라 검색 영역을 먼저 제한한다.

예:

목표 거리 = 5km

출발지에서 약 2~3km 정도의 검색 반경을 생성하고 해당 영역 안의 보행 가능한 도로 그래프만 사용한다.

검색 영역은 목표 거리와 허용 오차를 고려하여 결정한다.


## 4. 도로 그래프 구성

도로를 Graph 형태로 표현한다.

Node:
- 교차로
- 도로가 갈라지는 지점
- 도로 끝
- 필요한 경우 특정 시설이나 Waypoint와 연결되는 지점

Edge:
- 두 Node 사이의 실제 도로 구간

예:

Node A
 |
 | Edge 1
 |
Node B
 |
 | Edge 2
 |
Node C

각 Edge에는 실제 도로를 구성하는 위도/경도 Geometry가 존재해야 한다.

예:

Edge #100

from_node = 23
to_node = 41

geometry = [
    (lat1, lon1),
    (lat2, lon2),
    (lat3, lon3),
    ...
]

따라서 두 Node를 단순한 직선으로 연결하는 것이 아니라 실제 도로의 LineString을 따라 경로가 생성된다.

기본 도로망 데이터는 보행 가능한 실제 도로 Geometry를 제공할 수 있는 데이터가 필요하다.

보행자전용도로 등의 공공데이터는 기본 도로망 자체보다는 해당 도로의 추가적인 특징으로 결합하는 방식도 고려한다.


## 5. Edge Feature 생성

각 도로 Edge에 경로 탐색에 활용할 환경 데이터를 결합한다.

예:

Edge #100

길이                = 120m
평균 경사           = 2.1%
최대 경사           = 4.2%
가로등 수           = 3
CCTV 수             = 1
보행자전용도로 여부 = True
하천과의 거리       = 80m
녹지 관련 점수      = 0.7

가로등, CCTV, 화장실 등의 Point 데이터는 해당 Edge 주변 일정 범위에 존재하는 데이터를 Spatial Join 등의 방법으로 결합할 수 있다.

예:

Edge 주변 30m Buffer 생성
-> Buffer 안에 존재하는 가로등 검색
-> Edge의 lamp_count로 저장


## 6. 경사 Feature 계산

경사 정보는 도로 Geometry와 고도 데이터를 결합하여 계산한다.

예:

Edge 길이 = 100m
시작 고도 = 20m
끝 고도   = 25m

경사 = (25 - 20) / 100
     = 0.05
     = 약 5%

전체 Route에서는 다음과 같은 Feature를 추가로 계산한다.

- 평균 경사
- 최대 경사
- 누적 상승 고도
- 누적 하강 고도
- 일정 경사 이상인 구간의 비율

누적 상승 고도 예:

Edge 1 = +2m
Edge 2 = +5m
Edge 3 = -3m
Edge 4 = +8m

누적 상승 고도 = 2 + 5 + 8 = 15m


## 7. 핵심 지점(Waypoint) 후보 생성

전체 도로 Node를 직접 경유지로 지정하는 것이 아니라 소수의 핵심 Waypoint 후보를 생성한다.

예:

Start

W1 후보
- W1-A
- W1-B
- W1-C

W2 후보
- W2-A
- W2-B
- W2-C

Start

Waypoint를 선택할 때 고려할 수 있는 요소:

- 출발지와의 거리
- 목표 거리
- 진행 방향
- 사용자 필수 경유지
- 공원
- 하천
- 녹지
- 보행자전용도로
- 환경적 선호 요소

사용자가 특정 장소를 반드시 지나가야 한다고 요청한 경우에는 해당 장소와 가장 가까운 보행 도로 Node를 필수 Waypoint로 설정한다.


## 8. Waypoint 사이의 경로 후보 생성

예를 들어 핵심 경유지가 다음과 같다고 가정한다.

Start -> W1 -> W2 -> Start

Start-W1 사이에도 여러 실제 도로 경로가 존재할 수 있다.

Start -> W1

후보 A1
후보 A2
후보 A3

W1 -> W2

후보 B1
후보 B2
후보 B3

W2 -> Start

후보 C1
후보 C2
후보 C3

모든 가능한 경로를 탐색하면 경우의 수가 지나치게 증가하므로 각 구간에서 상위 K개의 유망한 경로만 유지한다.


## 9. Edge Cost 계산

Dijkstra 등의 그래프 탐색 알고리즘이 사용할 수 있도록 각 Edge에 Cost를 부여한다.

기본적인 최단거리 Dijkstra는 다음과 같다.

Edge Cost = 거리

RunStop에서는 사용자 선호를 반영하여 Cost를 확장한다.

예:

Edge Cost =
    거리 비용
    + 경사 비용
    + 야간 환경 비용
    + 보행 환경 비용

각 값의 단위가 다르므로 그대로 더하지 않고 일정 범위로 정규화한다.

예:

distance_cost = 0.3
slope_cost    = 0.7
darkness_cost = 0.2

사용자가 경사를 매우 중요하게 생각한다면 다음과 같이 가중치를 설정할 수 있다.

distance_weight = 0.2
slope_weight    = 0.5
light_weight    = 0.3

최종 Edge Cost:

Cost =
    0.2 * distance_cost
    + 0.5 * slope_cost
    + 0.3 * darkness_cost

Cost는 낮을수록 사용자의 요구사항에 적합한 도로로 정의한다.


## 10. Dijkstra의 역할

Dijkstra는 이미 생성된 전체 러닝 경로 중 가장 좋은 경로를 선택하는 알고리즘으로 사용하는 것이 아니다.

Dijkstra의 역할은 다음과 같다.

"Start와 W1 사이의 실제 도로 Graph에서 Edge Cost의 합이 가장 작은 경로를 찾는다."

예:

Start
  |
 Edge A cost=0.2
  |
 Node
  |
 Edge B cost=0.3
  |
 W1

총 Cost = 0.5

즉 다음과 같은 단위로 사용한다.

Start -> W1
W1 -> W2
W2 -> Start

일반적인 Dijkstra는 하나의 최적 경로를 반환하기 때문에 여러 후보가 필요하다면 다음 방법을 추가적으로 고려한다.

- K-Shortest Path
- Yen's Algorithm
- Dijkstra 반복 실행 + 기존 경로 패널티
- A* 기반 후보 생성

프로젝트 초기 구현에서는 하나의 구간에 대해 상위 몇 개의 유망한 경로를 생성하는 것을 목표로 한다.


## 11. 구간별 후보 유지

각 구간에서 가장 좋은 하나의 경로만 즉시 선택하지 않는다.

예:

Start -> W1

A1 = 1.3km / Cost 0.30
A2 = 1.5km / Cost 0.34
A3 = 1.4km / Cost 0.39

A1의 Cost가 가장 낮더라도 전체 경로에서는 A2가 더 좋은 결과를 만들 수 있다.

예:

A1 + B1 + C1 = 총 4.2km
A2 + B2 + C1 = 총 5.05km

사용자 목표가 5km라면 두 번째 조합이 전체적으로 더 적합할 수 있다.

따라서 각 구간에서 Top K 후보를 유지한 뒤 전체 경로 단위에서 다시 평가한다.


## 12. 전체 순환 경로 후보 생성

각 구간에서 살아남은 후보들을 조합한다.

예:

Start-W1:
A1, A2, A3

W1-W2:
B1, B2, B3

W2-Start:
C1, C2, C3

전체 Route 후보:

A1 + B1 + C1
A1 + B1 + C2
A1 + B1 + C3
A1 + B2 + C1
...
A3 + B3 + C3

후보 조합이 지나치게 많아질 경우 중간 단계에서 성능이 낮은 조합을 제거하는 방식이 필요하다.


## 13. Route Feature 계산

완성된 전체 경로를 기준으로 다시 Feature를 계산한다.

Edge Feature와 Route Feature는 구분한다.

Edge Feature:
- 개별 도로 구간을 평가
- Dijkstra 등의 탐색 과정에서 활용

Route Feature:
- 완성된 전체 러닝 코스를 평가
- 최종 Ranking에서 활용


전체 Route에서 계산할 Feature 예:

1. 총 거리
2. 목표 거리와의 차이
3. 평균 경사
4. 최대 경사
5. 누적 상승 고도
6. 누적 하강 고도
7. 높은 경사 구간 비율
8. 가로등 수
9. 1km당 가로등 수
10. CCTV 수
11. 화장실 수
12. 편의점 수
13. 보행자전용도로 비율
14. 하천 인접 구간 비율
15. 녹지 인접 구간 비율
16. 기타 환경 Feature


예:

Route A

총 거리               = 5.12km
목표 거리 오차        = 0.12km

평균 경사             = 1.7%
최대 경사             = 7.8%
누적 상승 고도        = 52m

가로등                = 42개
가로등/km             = 8.2

화장실                = 2개
편의점                = 4개

보행자전용도로 비율   = 73%
하천 인접 비율        = 41%


## 14. 위치 기반 시설 조건 계산

화장실이나 편의점은 단순 개수뿐만 아니라 위치를 고려할 수 있다.

예:

사용자 요구:
"약 2.5km 지점에 화장실이 있었으면 좋겠다."

Route A:
2.4km 지점에서 화장실까지 60m

Route B:
3.8km 지점에서 화장실까지 80m

Route C:
화장실 없음

이 경우 Route A에 높은 점수를 부여한다.

평가 요소:

- 원하는 경로 진행 거리와 실제 시설 위치의 차이
- 경로에서 시설까지의 실제 접근 거리

예:

목표 시설 위치 = 2.5km
허용 구간 = ±300m
경로와 시설 최대 거리 = 100m

조건을 만족하면 높은 점수를 부여한다.


## 15. Route Score 계산

전체 Route Feature를 사용자 요구사항과 비교하여 최종 점수를 계산한다.

Edge Cost와 달리 Route Score는 높을수록 좋은 경로로 정의할 수 있다.

예:

distance_score
slope_score
lighting_score
toilet_score
pedestrian_score
environment_score

사용자 선호:

distance_weight   = 0.20
slope_weight      = 0.30
lighting_weight   = 0.25
toilet_weight     = 0.10
pedestrian_weight = 0.15

Route Score =

    distance_score   * 0.20
  + slope_score      * 0.30
  + lighting_score   * 0.25
  + toilet_score     * 0.10
  + pedestrian_score * 0.15


각 Feature는 일정 범위의 점수로 변환한다.

예:

화장실 점수

0개 -> 0.0
1개 -> 0.8
2개 -> 1.0
3개 이상 -> 1.0

화장실의 경우 일정 개수 이상부터 효용이 크게 증가하지 않으므로 상한을 설정한다.


## 16. 최종 필수 조건 재검증

높은 Route Score를 받았더라도 필수 조건을 만족하지 못하면 추천 후보에서 제외한다.

예:

사용자 목표 거리 = 5km
허용 오차 = ±500m

Route A = 5.2km -> 통과
Route B = 4.8km -> 통과
Route C = 6.7km -> 탈락

추가 검증 예:

- 실제 도로가 연결되어 있는가
- 보행 불가능 구간이 포함되어 있지 않은가
- 필수 Waypoint를 실제로 통과하는가
- 목표 거리 허용 오차를 만족하는가
- 사용자가 지정한 최대 경사를 초과하지 않는가
- 필수 시설 조건을 만족하는가


## 17. 최종 Top 3 선정

필수 조건을 모두 통과한 경로를 Route Score 기준으로 정렬한다.

예:

Route A = 0.91
Route B = 0.86
Route C = 0.81
Route D = 0.74
Route E = 0.71

최종 결과:

1순위 Route A
2순위 Route B
3순위 Route C

단순히 비슷한 경로 3개를 반환하기보다는 경로 간 중복도를 계산하여 가능한 경우 서로 다른 특징을 가진 경로를 제공하는 것도 고려한다.

예:

1순위 = 조건을 가장 많이 만족하는 경로
2순위 = 조금 더 평탄한 경로
3순위 = 조금 더 밝거나 시설이 많은 경로


## 18. 추천 가능한 경로가 없는 경우

모든 상황에서 반드시 3개의 경로를 반환하지 않는다.

다음 조건에서는 "추천 가능한 경로 없음"을 반환할 수 있다.

- 필수 조건을 만족하는 경로가 없음
- 목표 거리 오차가 허용 범위를 지나치게 초과
- 보행 도로가 연결되지 않음
- 필수 Waypoint를 포함한 순환 경로 생성 불가능
- 필수 시설 조건 충족 불가능

필요하다면 사용자에게 완화 가능한 조건을 알려준다.

예:

"5km ±300m 범위에서는 조건을 만족하는 경로가 없습니다."

"거리 허용 범위를 ±700m로 변경하면 2개의 경로를 추천할 수 있습니다."

"화장실 2곳 이상 조건을 만족하는 경로가 없어 화장실 1곳 이상으로 완화할 수 있습니다."


## 19. 사용자 경로 선택

최종적으로 3개의 후보를 사용자에게 제공하고 사용자가 하나를 선택한다.

이 단계의 사용자 선택 결과는 향후 개인화 및 AI 학습 데이터로 활용할 수 있다.

예:

사용자 요구:
- 평지 중요도 높음
- 야간 밝기 중요도 높음
- 화장실 중요도 보통

후보:
Route A
Route B
Route C

사용자 선택:
Route B

이를 다음과 같은 데이터 형태로 저장할 수 있다.

사용자 Preference
+
Route A Feature
+
Route B Feature
+
Route C Feature
+
사용자 선택 Route B


## 20. 사용자 피드백 반영

사용자가 선택한 경로를 실제 이용한 이후 피드백을 제공할 수 있다.

예:

"경사가 생각보다 높았다."
"좀 더 평평한 코스를 원한다."
"가로등은 충분했다."

이를 사용자 Preference에 반영한다.

예:

기존:
slope_preference = 0.3

피드백:
"경사를 더 낮춰달라."

변경:
slope_preference = 0.4

또는 사용자가 실제로 만족했던 Route Feature를 누적하여 사용자의 적정 경사 범위를 학습할 수 있다.

예:

사용자가 만족한 경로들의 평균:

평균 경사       = 1.8%
최대 경사       = 6%
누적 상승       = 40m

향후 추천에서 이 값과 가까운 경로에 높은 점수를 부여한다.


## 21. AI 적용 후보

현재 알고리즘의 각 단계 중 AI 적용을 고려할 수 있는 부분은 다음과 같다.


### AI 후보 1. Waypoint 선정

입력:

- 사용자 요구
- 출발지
- 목표 거리
- 주변 시설
- 주변 환경
- 도로 구조

출력:

- 추천 Waypoint 후보

기존 알고리즘으로도 구현할 수 있으며 향후 학습 모델로 대체 가능한 영역이다.


### AI 후보 2. Edge Cost 계산

현재 방식:

사람이 직접 가중치를 정의

Cost =
distance * w1
+ slope * w2
+ lighting * w3
+ ...

향후 방식:

사용자의 과거 선택 데이터를 이용하여 각 Feature가 실제 경로 선택에 미치는 영향을 학습한다.


### AI 후보 3. Route Ranking

입력:

사용자 Preference
+
Route Feature

출력:

해당 사용자가 해당 경로를 선호할 점수

예:

User Preference + Route A -> 0.73
User Preference + Route B -> 0.91
User Preference + Route C -> 0.64

이 점수를 이용하여 후보 경로의 순서를 결정할 수 있다.

AI 적용 후보 중 비교적 명확하게 학습 문제로 정의하기 쉬운 영역이다.


### AI 후보 4. 사용자 개인화

사용자의 과거 선택과 피드백을 기반으로 선호값을 자동 조정한다.

예:

사용자가 지속적으로
- 평균 경사가 낮은 경로 선택
- 가로등이 많은 경로 선택
- 약간 더 긴 코스도 허용

한다면 이를 학습하여 다음 추천에 반영한다.


## 22. 기존 알고리즘과 AI의 역할 구분

초기 버전:

도로 Graph
-> 사람이 정의한 Edge Cost
-> Dijkstra / K-Shortest Path
-> Route Feature 계산
-> 사람이 정의한 Route Score
-> Top 3

AI 적용 버전:

도로 Graph
-> 학습된 Edge Cost 또는 기존 Cost
-> Dijkstra / K-Shortest Path
-> Route Feature 계산
-> AI Ranking Model
-> 개인화된 Top 3

그래프 탐색 자체는 이미 검증된 Dijkstra, A*, K-Shortest Path 등의 알고리즘을 유지하고,
"어떤 도로가 사용자에게 좋은가"와
"어떤 완성 경로를 사용자가 선호할 것인가"
부분을 AI 학습 후보로 두는 것이 우선적으로 고려 가능하다.


## 23. 전체 알고리즘 의사코드

function recommend_route(user_request):

    # 사용자 요구 분석
    hard_conditions = parse_hard_conditions(user_request)
    preferences = parse_preferences(user_request)
    near_conditions = parse_near_conditions(user_request)

    # 탐색 영역 결정
    search_area = calculate_search_area(
        start=user_request.start,
        target_distance=user_request.distance
    )

    # 실제 보행 도로 그래프 추출
    graph = load_walking_graph(search_area)

    # 도로 Edge Feature 구성
    for edge in graph.edges:

        edge.length = calculate_length(edge)

        edge.elevation = get_elevation(edge)
        edge.avg_slope = calculate_avg_slope(edge)
        edge.max_slope = calculate_max_slope(edge)

        edge.lamp_count = count_near_lamps(edge)
        edge.cctv_count = count_near_cctv(edge)

        edge.pedestrian = check_pedestrian_road(edge)

        edge.environment = calculate_environment_features(edge)


    # 사용자 선호 기반 Edge Cost 생성
    for edge in graph.edges:

        edge.cost = calculate_edge_cost(
            edge=edge,
            preferences=preferences
        )


    # 핵심 Waypoint 후보 생성
    waypoint_sets = generate_waypoint_candidates(
        graph=graph,
        start=user_request.start,
        target_distance=user_request.distance,
        hard_conditions=hard_conditions,
        preferences=preferences
    )


    segment_candidates = []


    # 각 Waypoint 조합 탐색
    for waypoint_set in waypoint_sets:

        points = [
            start,
            waypoint_1,
            waypoint_2,
            ...,
            start
        ]

        segments = []

        # 각 핵심 지점 사이의 상위 K개 경로 후보 생성
        for point_a, point_b in consecutive(points):

            paths = find_k_best_paths(
                graph,
                point_a,
                point_b,
                edge_cost
            )

            segments.append(paths)


        # 구간 후보들을 조합하여 전체 순환 경로 후보 생성
        routes = combine_segment_candidates(segments)

        segment_candidates.extend(routes)


    valid_routes = []


    # 전체 경로 평가
    for route in segment_candidates:

        route.features = calculate_route_features(route)

        route.features.distance = calculate_total_distance(route)

        route.features.avg_slope = calculate_average_slope(route)

        route.features.max_slope = calculate_max_slope(route)

        route.features.elevation_gain = calculate_elevation_gain(route)

        route.features.lamp_density = calculate_lamps_per_km(route)

        route.features.toilets = find_toilets_near_route(route)

        route.features.stores = find_stores_near_route(route)

        route.features.pedestrian_ratio =
            calculate_pedestrian_ratio(route)


        # 필수 조건 확인
        if not satisfies_hard_conditions(
            route,
            hard_conditions
        ):
            continue


        # 근접 조건 평가
        route.near_score = evaluate_near_conditions(
            route,
            near_conditions
        )


        # 최종 경로 점수 계산
        route.score = calculate_route_score(
            route.features,
            preferences,
            route.near_score
        )


        valid_routes.append(route)


    # 조건을 만족하는 경로 없음
    if len(valid_routes) == 0:

        return {
            "status": "NO_ROUTE",
            "reason": find_failure_reason()
        }


    # 최종 Ranking
    valid_routes.sort(
        by=route.score,
        descending=True
    )


    # 지나치게 유사한 경로 제거
    valid_routes =
        remove_highly_overlapping_routes(valid_routes)


    # 상위 3개
    return valid_routes[:3]


## 24. 핵심 정리

RunStop의 추천 알고리즘은 다음과 같이 정리할 수 있다.

1. 사용자 요구를 필수 조건, 선호 조건, 근접 조건으로 분리한다.

2. 목표 거리를 이용하여 검색할 도로 영역을 제한한다.

3. 실제 보행 가능한 도로를 Node와 Edge로 구성된 Graph로 가져온다.

4. 각 Edge에 거리, 경사, 가로등, 보행 환경 등의 Feature를 결합한다.

5. 사용자 요구에 따라 각 Edge의 Cost를 계산한다.

6. Start -> W1 -> W2 -> ... -> Start 형태의 핵심 Waypoint 후보를 만든다.

7. 각 핵심 Waypoint 사이에서 Dijkstra, A*, K-Shortest Path 등을 이용해 유망한 실제 도로 경로 후보를 생성한다.

8. 각 구간의 가장 좋은 경로 하나만 즉시 선택하지 않고 상위 K개 후보를 유지한다.

9. 각 구간 후보를 조합하여 여러 개의 전체 순환 경로를 만든다.

10. 완성된 경로에서 총 거리, 평균 경사, 최대 경사, 누적 상승 고도, 시설 접근성 등의 Route Feature를 계산한다.

11. 필수 조건을 다시 검사하여 만족하지 못하는 경로를 제거한다.

12. Route Feature와 사용자 선호를 비교하여 최종 Route Score를 계산한다.

13. 지나치게 유사한 경로를 제거하고 최종 Top 3를 반환한다.

14. 조건을 만족하는 경로가 존재하지 않을 경우 억지로 추천하지 않고 추천 가능한 경로가 없음을 반환한다.

15. 사용자의 최종 선택 및 이후 피드백을 저장하여 향후 개인화와 AI Ranking 모델의 학습 데이터로 활용한다.
