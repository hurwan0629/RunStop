# 회원 정지

관리자가 회원을 기간 정지 또는 영구 정지하고 기존 관리자 메모에 사유를 추가합니다.

## 엔드포인트

- `PATCH /api/admin/users/suspension`

## 요청 스키마

```json
{
  "userIdx": 123,
  "suspendedUntil": "2099-09-13T18:00:00+09:00",
  "reason": "반복적인 운영 정책 위반"
}
```

- 모든 필드는 필수입니다.
- `userIdx`: 양의 정수인 회원 idx.
- `suspendedUntil`: 미래의 ISO 8601 종료 시각. `Z` 또는 시간대 오프셋이 필요합니다. 예시 날짜는 실제 종료 시각으로 바꿉니다.
- `suspendedUntil: null`이면 영구 정지입니다. 필드 생략은 허용하지 않습니다.
- `reason`: 앞뒤 공백 제거 후 1~2000자의 한 줄 문자열입니다.
- 이미 정지된 회원도 요청할 수 있습니다. 종료 시각을 새 값으로 바꾸고 사유를 추가합니다.

## 응답 스키마

```json
{
  "success": true,
  "data": {
    "userIdx": 123,
    "status": "SUSPENDED",
    "suspendedUntil": "2099-09-13T09:00:00.000Z"
  }
}
```

영구 정지 응답의 `suspendedUntil`은 `null`입니다. 날짜 응답은 UTC입니다.

## 인증/권한

- `authenticate` 이후 `requireAdmin`을 적용합니다.
- Bearer JWT가 필요하며 DB에서 확인한 현재 권한이 `ADMIN`이어야 합니다.

## 검사하는 내용

- 요청 필드 형식 및 미래 종료 시각.
- 대상 회원 존재 여부.
- 탈퇴 회원은 정지할 수 없습니다.

## 저장/변경하는 상태

- `[service.users.status]`: `SUSPENDED`.
- `[service.users.suspended_until]`: 지정 종료 시각 또는 `NULL`.
- `[service.users.admin_memo]`: 기존 내용 뒤에 줄바꿈으로 `[2026-09-06 15:00:00 KST] 정지 사유: 반복적인 운영 정책 위반` 형식 추가. 대괄호의 시간은 종료 시각이 아닌 처리 시각이며 한국 시간입니다.
- `[service.users.updated_at]`: 처리 시각.
- `login_id`, `password_hash`는 변경하지 않습니다.
- 대상 행 잠금과 트랜잭션으로 상태 변경과 메모 추가를 함께 처리합니다.

## 오류

| HTTP | 코드 | 의미 |
|---|---|---|
| 400 | `INVALID_ADMIN_SUSPENSION_REQUEST` | 요청 형식 또는 종료 시각 오류 |
| 401 | 인증 미들웨어 오류 코드 | 인증 실패 |
| 403 | `ADMIN_REQUIRED` | 관리자 권한 없음 |
| 404 | `USER_NOT_FOUND` | 대상 회원 없음 |
| 409 | `WITHDRAWN_USER` | 탈퇴 회원 |

## 구현 범위

정지 상태 저장만 추가합니다. 해제 API와 인증 로직 변경은 포함하지 않습니다.
현재 JWT 인증에는 영구 정지 차단이 누락되어 있어 기존 토큰의 접근 차단은 별도 보완이 필요합니다.
