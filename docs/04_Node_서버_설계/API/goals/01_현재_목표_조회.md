# 현재 목표 조회

## 엔드포인트

- `GET /api/goals/current`

## 요청 스키마

```json
{}
```

## 응답 스키마

```json
{
  "success": true,
  "data": {
    "goal": {
      "idx": 1,
      "goalType": "WEEKLY",
      "targetDistance": 20000,
      "status": "ACTIVE",
      "startDate": "2026-09-01",
      "endDate": "2026-09-07"
    },
    "progress": {
      "distance": 5000,
      "rate": 25
    }
  }
}
```

## 인증/인가

- `authenticate`

## 검사하는 내용

- 액세스 토큰 유효 여부
- 만료된 목표 상태 갱신 필요 여부
- 목표 종료일 당일까지는 진행 가능한 목표로 유지
- 종료일 다음날부터 목표 기간 내 러닝 거리 합산 결과로 `SUCCESS` 또는 `FAILED` 판정

## 조회하는 상태

- 목표 idx `[running_goals.idx]`
- 사용자 idx `[running_goals.users_idx]`
- 목표 종류 `[running_goals.goal_type]`
- 목표 거리 `[running_goals.target_distance]`
- 목표 상태 `[running_goals.status]`
- 시작일 `[running_goals.start_date]`
- 종료일 `[running_goals.end_date]`
- 러닝 거리 `[running_sessions.distance]`
- 러닝 시작 시각 `[running_sessions.started_at]`

## 저장/변경하는 상태

- 만료된 목표 상태 `[running_goals.status]`
- 목표 종료 시각 `[running_goals.finished_at]`

## 구현 메모

- `goals.service.refreshExpiredGoals(userIdx)`에서 만료 목표 갱신만 분리해서 처리합니다.
- `GET /api/goals/current`는 목표를 보여주기 전에 `refreshExpiredGoals`를 먼저 호출합니다.
- `end_date < CURRENT_DATE`인 경우에만 만료로 판단하므로 종료일 당일에는 계속 진행 가능합니다.
- 진행률은 DB의 `CURRENT_DATE`를 기준으로 목표 시작일부터 오늘까지의 `running_sessions.status <> 'IN_PROGRESS'` 거리 합계를 사용합니다.
- 현재 단계에서는 별도 cron 없이 조회 시점 lazy update로 처리합니다.
- 추후 업그레이드 시 삭제할 요소: 화면 진입마다 발생하는 lazy update 의존.
- 추후 업그레이드 시 추가할 내용: cron 또는 scheduler에서 동일 갱신 함수를 주기 실행, 사용자별 `ACTIVE` 목표 중복 방지 partial unique index 추가.
