# 목표 중지

## 엔드포인트

- `POST /api/goals/:goalIdx/stop`

## 요청 스키마

```json
{
  "params": {
    "goalIdx": 1
  }
}
```

## 응답 스키마

```json
{
  "success": true,
  "data": {
    "idx": 1,
    "status": "STOPPED",
    "finishedAt": "2026-09-01T12:00:00.000Z"
  }
}
```

## 인증/인가

- `authenticate`

## 검사하는 내용

- 목표 idx 형식
- 목표 소유자 일치 여부
- 목표가 중지 가능한 상태인지 여부
- 만료된 목표 상태 갱신 필요 여부

## 조회하는 상태

- 목표 idx `[running_goals.idx]`
- 사용자 idx `[running_goals.users_idx]`
- 목표 상태 `[running_goals.status]`

## 저장/변경하는 상태

- 목표 상태 `[running_goals.status]`
- 목표 종료 시각 `[running_goals.finished_at]`

## 구현 메모

- 목표 중지 전에 `goals.service.refreshExpiredGoals(userIdx)`를 먼저 실행합니다.
- 만료 갱신 이후에도 `ACTIVE` 상태인 목표만 `STOPPED`로 변경할 수 있습니다.
- 이미 `SUCCESS`, `FAILED`, `STOPPED` 상태인 목표는 중지할 수 없습니다.
- 추후 업그레이드 시 삭제할 요소: 목표 중지 요청마다 수행하는 lazy update 의존.
- 추후 업그레이드 시 추가할 내용: scheduler 기반 만료 갱신, 목표 상태 변경 이력 테이블.
